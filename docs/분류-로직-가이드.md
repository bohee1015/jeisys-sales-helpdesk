# 분류 · 필수값 추출 로직 가이드

요청자가 입력한 문장이 **어떤 카테고리로 분류되고**, **필수값이 어떻게 채워지는지**를 유지보수 관점에서 정리한 문서입니다.
LLM(OpenAI 등)은 쓰지 않습니다. 전부 **키워드 포함 여부 + 정규식 규칙 + 가중치 점수**로 동작합니다.

> 코드가 바뀌면 이 문서도 함께 고쳐 주세요. 작성 기준: 2026-09-18 (점수 체계 개편 이후).

---

## 0. 고치기 전에 — 명령 두 개

| 명령 | 언제 | 무엇을 |
|---|---|---|
| `npm run check:nlp` | 키워드·규칙을 고칠 때마다 | 실제 유형의 문장 58개를 통과시켜 **기대한 분류·필수값과 같은지** 비교. 하나라도 틀리면 실패로 끝남 |
| `npm run check:keywords` | 키워드를 추가할 때 | 같은 키워드가 두 소분류에 있는지, 한 키워드가 다른 소분류 키워드의 일부인지, 2글자 이하인지 표시 |

테스트 문장은 `scripts/nlp-cases.json`에 있습니다. **잘못 분류된 실제 사례를 발견하면 먼저 이 파일에 문장과 기대 결과를 추가**하고, 규칙을 고친 뒤 `npm run check:nlp`가 통과하는지 확인하는 순서가 안전합니다. (공개 저장소이므로 병원명·인명은 가명으로 바꿔 넣습니다.)

---

새로 받은 실제 문장 묶음을 먼저 따로 돌려 보려면 `npm run check:nlp -- --cases 파일경로` (같은 JSON 형식). 통과하면 `scripts/nlp-cases.json`에 합칩니다.

요청자가 채팅에 문장을 보내면 [`app/lib/helpdesk.ts`](../app/lib/helpdesk.ts)의 `handleChatMessage`가 아래 순서로 처리합니다.

|---|---|---|
| ① | 이미 **되묻는 중인 요청**이 있으면, 이번 답변을 그 필드 값으로 **그대로** 넣는다 (다시 분석하지 않음) | `helpdesk.ts` `continueCollectingInfo` |

## 2. 점수 체계

분류 신호는 **전부 [`categories.ts`](../app/lib/categories.ts)에** 있습니다. 소분류마다 두 종류의 신호를 가집니다.

### 문장 정규화

비교 전에 문장과 키워드 모두 **공백을 전부 지우고 소문자로** 바꿉니다.
"장비 하나 잡아 주세요" → `장비하나잡아주세요`. 아래의 모든 패턴은 이 형태 기준입니다.

### 신호 ① 키워드 (`keywords`) — 하나당 1점

- 문장에 **포함**되어 있으면 1점. 단어의 일부여도 걸립니다 ("팁"은 "알파팁"에도).
- 같은 소분류 안에서 한 키워드가 다른 키워드에 포함되면 **긴 것 하나만** 셉니다. "명세서"와 "거래명세서"가 둘 다 걸려도 1점입니다. 그래서 표기 변형을 늘려도 점수가 부풀지 않습니다.
- 짧고 흔한 말("변경", "확인", "리스")은 키워드로 두지 않고 아래 패턴에 맥락과 함께 둡니다.

### 신호 ② 맥락 패턴 (`signals`) — 각각 정한 점수

정규식 + 가중치입니다. "동사 + 목적어"처럼 키워드 하나로는 못 잡는 표현을 여기서 잡습니다.

```ts
sig(/(장비|하나|한대|\d+대).{0,4}(잡아|잡고|확보|준비)/, 3)   // "장비 하나 잡아주세요" → 장비확보 +3
sig(/설치.{0,60}회수/, 2, /보상/)                          // 설치…회수는 데모, 단 "보상"이 있으면 무시
```

- `.{0,N}`은 "사이에 N글자까지 다른 말이 끼어도 됨"입니다.
- 세 번째 인자(`unless`)에 있는 말이 문장에 있으면 그 신호는 무시합니다.
- 가중치 기준: **1 = 약한 단서**(다른 소분류에도 흔히 나오는 말), **2 = 뜻이 분명한 말**, **3 이상 = 그 소분류가 거의 확정**되는 표현.

### 신호 ③ 대분류 단서 (`anchor`)

소분류 점수가 하나도 안 나왔을 때만 씁니다. "파이프드라이브 확인 부탁"처럼 무슨 업무인지는 모르지만 어느 대분류인지는 분명한 경우, 그 대분류의 소분류만 고르게 합니다. 단서가 **하나의 대분류만** 가리킬 때만 작동합니다.

### 최종 판정 (`classifyDetailed`)

| 상황 | 결과 |
|---|---|
| 1등이 단독 | 그 소분류로 접수 시작 |
| 1·2등 동점, **같은 대분류** | 대분류만 제안 → 요청자가 소분류만 고름 |
| 1·2등 동점, **다른 대분류** | 단정하지 않음 → 요청자가 대분류부터 고름 |
| 후보 없음, 대분류 단서 1개 | 대분류만 제안 |
| 후보 없음, 단서도 없음 | 요청자가 대분류부터 고름 |

### 여러 건 분리 (`classifyMultipleSubcategories`)

점수 계산보다 **먼저** 확인합니다.

- 연결어 **"및" · "그리고" · "그리고요" · "동시에"** 가 있고
- "데모"가 없고
- **2점 이상**인 대분류가 **둘 이상**이면 → 대분류별 1등 소분류 2개로 나눠 접수

> 2점 미만 대분류는 무시하므로 "품목 및 수량"처럼 흔한 "및"으로는 갈라지지 않습니다.

### 계산 예시

> "자연의원 덴서티 장비 하나 잡아주세요"

| 소분류 | 걸린 신호 | 점수 |
|---|---|---|
| 장비납품 · 장비확보 | `(장비|하나|…).{0,4}(잡아|…)` +3, `덴서티.{0,10}하나` +1 | **4** |
| (다른 소분류) | 없음 | 0 |

→ 장비확보. 필수값: 병원명 `자연의원`, 장비명 및 수량 `덴서티 1대` (자동), 필요 시점 → 되물음.

> "데모 팁 추가 출고 부탁드립니다 한빛의원 알파팁 10개 택배 기안완료"

| 소분류 | 걸린 신호 | 점수 |
|---|---|---|
| 출고 · 소모품 | 키워드 `알파팁` 1, `알파팁|소모품` +1, `팁.{0,12}(출고|택배…)` +2, `기안` +1 | **5** |
| 데모 · 신규등록 | 키워드 `데모` 1, `데모` +2, `데모.{0,10}(…부탁)` +1 | 4 |

→ 출고 · 소모품 (출고 목적: 추가데모팁). 예전에는 "데모" 한 단어로 무조건 데모로 갔습니다.

## 5. 무엇을 바꾸려면 어디를 고치나

| 하고 싶은 일 | 고칠 파일 · 위치 |
|---|---|
| 새 표현으로도 분류되게 하기 (한 단어) | `categories.ts` → 해당 소분류 `keywords` 배열에 추가 |
| 두 말이 **함께** 나올 때, 또는 동사+목적어 표현 잡기 | `categories.ts` → 해당 소분류 `signals`에 `sig(/패턴/, 점수)` 추가 |
| 어떤 말이 있을 때는 신호를 무시하기 | `sig(...)`의 세 번째 인자 `unless` |
| 대분류만이라도 짚어 주는 단서 추가 | `categories.ts` → 해당 대분류 `anchor` |
| 필수값 항목 추가 · 삭제 · 순서 변경 (되묻는 순서 = 배열 순서) | `categories.ts` → 해당 소분류 `fields` |
| 새로 만든 필드를 문장에서 자동으로 뽑기 | `fieldExtraction.ts` `switch`에 필드 id 추가 + 필요하면 `extract.ts`에 함수 추가 |
| 병원명 뒤 단어가 지점명으로 잘못 붙음 | `extract.ts` → `REQUEST_WORDS`에 그 단어 추가 (분류 키워드는 자동 반영됨) |
| 품목명 인식 추가 (새 장비 등) | `extract.ts` → `EQUIPMENT_KEYWORDS`(대수로 셈) 또는 `PRODUCT_KEYWORDS`(긴 이름을 앞에), 모델명은 `PRODUCT_VARIANTS` |
| 캐피탈사 약칭 추가 | `extract.ts` → `KNOWN_CAPITAL_COMPANIES` |
| 선행 업무 추가 (예: 판촉물에도 기안 승인) | `categories.ts` → 해당 소분류에 `prerequisite` |
| 예/아니오 판정 표현 추가 | `yesNo.ts` → `NEGATIVE_PATTERNS` / `POSITIVE_PATTERNS` |
| 2건 분리 연결어 | `nlp.ts` → `MULTI_REQUEST_CONNECTORS` |
| 테스트 문장 추가 | `scripts/nlp-cases.json` |

### 키워드·패턴을 추가할 때 체크리스트

1. **먼저 `scripts/nlp-cases.json`에 그 문장을 넣고** `npm run check:nlp`로 지금 어떻게 나오는지 본다.
2. **너무 짧은 단어는 키워드로 두지 않는다** — 2글자 이하는 다른 단어 속에 숨어 있을 확률이 높다. 맥락 패턴(`sig`)으로 앞뒤 말과 함께 잡는다.
3. **다른 소분류에 같은(또는 포함 관계인) 키워드가 없는지** `npm run check:keywords`로 확인한다. 있으면 동점이 나서 매번 되묻게 된다.
4. **가중치는 작게 시작한다.** 3 이상은 그 표현이 나오면 그 소분류가 거의 확정일 때만.
5. 고친 뒤 `npm run check:nlp`가 통과하는지 확인한다. 통과하지 않으면 다른 소분류가 깨진 것이다.
