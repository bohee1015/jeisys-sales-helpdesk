# 분류 · 필수값 추출 로직 가이드

요청자가 입력한 문장이 **어떤 카테고리로 분류되고**, **필수값이 어떻게 채워지는지**를 유지보수 관점에서 정리한 문서입니다.
LLM(OpenAI 등)은 쓰지 않습니다. 전부 **키워드 포함 여부 + 정규식 규칙**으로 동작합니다.

> 코드가 바뀌면 이 문서도 함께 고쳐 주세요. 표의 값은 작성 시점(2026-09-17) 코드 기준입니다.

---

## 1. 한눈에 보는 흐름

요청자가 채팅에 문장을 보내면 [`app/lib/helpdesk.ts`](../app/lib/helpdesk.ts)의 `handleChatMessage`가 아래 순서로 처리합니다.

| 순서 | 무엇을 하나 | 코드 위치 |
|---|---|---|
| ① | 이미 **되묻는 중인 요청**이 있으면, 이번 답변을 그 필드 값으로 **그대로** 넣는다 (다시 분석하지 않음) | `helpdesk.ts` `continueCollectingInfo` |
| ② | **선행 업무 확인 중**이면 답변을 예/아니오로 판정한다 | `helpdesk.ts` `answerPrerequisiteInChat` |
| ③ | 요청자가 분류를 **직접 골랐으면** 그 분류로 접수를 시작한다 | `helpdesk.ts` `handleChatMessage` |
| ④ | "및/그리고"로 **서로 다른 업무 두 개**가 이어져 있으면 2건으로 나눈다 | `nlp.ts` `classifyMultipleSubcategories` |
| ⑤ | **분류** — 소분류 하나를 고른다. 확신이 없으면 요청자에게 고르게 한다 | `nlp.ts` `classifySubcategory` |
| ⑥ | **필수값 추출** — 문장에서 병원명·날짜·품목 등을 뽑는다 | `fieldExtraction.ts` `extractAllFields` |
| ⑦ | 빠진 필수값이 있으면 **첫 번째 하나만** 되묻는다 → ①로 돌아감 | `fieldExtraction.ts` `findFirstMissingField` |
| ⑧ | 필수값이 다 차면: 선행 업무가 있는 소분류는 확인 질문, 없으면 **접수 완료** | `helpdesk.ts` `startNewRequest` |

## 2. 분류 규칙 — 판단 순서

분류는 **위에서부터 먼저 걸리는 규칙이 이깁니다.**

### ① 데모 예외 규칙 (점수 계산보다 먼저)

`nlp.ts` `classifySubcategory` 첫 두 줄, `classifyDemo`

- 문장에 **"데모"** 가 있으면 → 무조건 데모 대분류
- "데모"가 없어도 **"설치" + "회수"** 가 같이 있고 **"보상"이 없으면** → 데모 대분류
- 데모 안에서 소분류는:
  - "특이사항" 포함 → **특이사항**
  - "변경" 또는 "연장" 포함 → **일정변경**
  - 그 외 → **신규등록**

> ⚠️ 이 규칙은 키워드 점수보다 먼저 실행됩니다. "데모"라는 단어가 들어간 문장은 다른 카테고리 키워드가 아무리 많아도 데모로 갑니다.

### ② 키워드 점수

`nlp.ts` `buildScores` + `categories.ts`의 각 소분류 `keywords`

1. 문장과 키워드 모두 **공백을 전부 지우고 소문자로** 바꾼 뒤 비교합니다.
2. 소분류마다 **문장 안에 포함된 키워드의 개수**가 그 소분류의 점수입니다.
3. 점수가 1 이상인 소분류만 후보가 됩니다.

> ⚠️ **"포함"만 보기 때문에 단어의 일부여도 걸립니다.** "팁"은 "알파팁"에도 걸리고, "확보"는 "자리 확보"에도 걸립니다.
>
> ⚠️ **키워드 개수가 곧 점수입니다.** 같은 말의 표기 변형을 여러 개 넣으면 그 소분류 점수가 부풀려집니다.
> 예: 장비확보의 `납품일정`, `납품 일정`, `납품일` — 공백을 지우면 앞의 둘은 같은 말이고 `납품일`은 그 일부라서,
> 문장에 "납품 일정"이 한 번만 나와도 **3점**이 됩니다.

### ③ 가산점 규칙 (BOOST_RULES)

`nlp.ts` `BOOST_RULES` — 키워드만으로는 구분이 안 되는 경우를 위한 보정입니다. 조건이 맞으면 해당 소분류에 점수를 **더합니다** (없던 후보면 새로 만듭니다).

| 조건 | 가산 대상 | 점수 | 왜 있나 |
|---|---|---|---|
| "선출고" 포함 | 장비납품 · 선출고 | +1 | 선출고를 우선하되, "납품일정" 같은 확실한 신호는 덮어쓰지 않도록 +1만 |
| "인증카드" 포함 | 출고 · 판촉물 | +1 | |
| "리스" 또는 "무이자" 포함 | 정산 · 무이자리스신청 | +2 | |
| "보상" **그리고** "회수" 포함 | 장비납품 · 보상회수 | +2 | "보상 장비 회수"처럼 사이에 말이 끼면 키워드 `보상회수`로 못 잡음 |
| "수정" **그리고** ("회수" 또는 "납품" 또는 "N일") | 장비납품 · 일정변경 | +1 | "변경" 대신 "수정"을 쓰는 경우. 범위를 좁혀 사업자등록증 수정 등과 안 겹치게 |
| ("팁" 또는 "카트리지") **그리고** "주문" | 쇼핑몰 · 배송 | +3 | 팁+주문은 사내 출고가 아니라 쇼핑몰 구매 건 |
| "크레딧" 또는 "크래딧" 포함 | 쇼핑몰 · 크레딧 | +1 | "팁이 몇 개 남았다" 같은 배경 설명 때문에 소모품과 동점 나는 것 방지 |
| "파이프드라이브" **그리고** ("등록" 또는 "거래처") | 파이프드라이브 · 거래처등록 | +2 | "파이프드라이브**에** 등록"처럼 조사가 끼는 경우 |

> 가산점 규칙은 `categories.ts`가 아니라 **`nlp.ts`에 코드로** 들어 있습니다. 키워드를 찾을 때 두 파일을 모두 봐야 합니다.

### ④ 최종 판정

- 후보가 **없으면** → 요청자에게 대분류/소분류를 직접 고르게 함
- 1등과 2등 점수가 **같으면** → 단정하지 않고 요청자에게 고르게 함 (PRD 5번 규칙)
- 1등이 **단독이면** → 그 소분류로 접수 시작

### ⑤ 여러 건 분리

`nlp.ts` `classifyMultipleSubcategories` — 분류(②~④)보다 **먼저** 확인합니다.

- 문장에 연결어 **"및" · "그리고" · "그리고요" · "동시에"** 중 하나가 있고
- "데모"가 없고
- 점수 후보가 **서로 다른 대분류 2개 이상**이면
- → 대분류별 최고점 소분류 **2개**로 나눠 각각 접수

> ⚠️ "및"은 "파이프드라이브 및 SAP"뿐 아니라 "품목 및 수량" 같은 일반 문장에도 흔히 나옵니다. 이때 서로 다른 대분류 키워드가 우연히 두 개 걸리면 의도치 않게 2건으로 쪼개집니다.

### 계산 예시

> "가온의원 크레딧 차감 확인 부탁드립니다. 팁이 3개밖에 안남았다고 합니다"

| 단계 | 결과 |
|---|---|
| 데모 예외 | "데모" 없음, "설치+회수" 없음 → 통과 |
| 여러 건 분리 | 연결어 없음 → 통과 |
| 키워드 점수 | 쇼핑몰·크레딧 `크레딧` **1점** / 출고·소모품 `팁` **1점** |
| 가산점 | "크레딧" 포함 → 쇼핑몰·크레딧 +1 → **2점** |
| 판정 | 2점 vs 1점 → **쇼핑몰 · 크레딧** |

## 4. 필수값 추출 규칙

`fieldExtraction.ts`가 필드 id별로 `extract.ts`의 함수를 부릅니다. **못 찾으면 비워 두고 챗봇이 되묻습니다.**

| 필드 id | 화면 이름 | 추출 규칙 | 코드 |
|---|---|---|---|
| clientName | 거래처명(병원명) | `OO의원 / 병원 / 피부과 / 외과 / 내과 / 한의원 / 클리닉` (앞 1~6글자). 바로 뒤에 공백 하나 두고 짧은 단어가 오면 지점명으로 붙임. 단, 그 단어가 제외어 목록 `BRANCH_STOPWORDS`에 있거나 **뒤에 "원장"이 이어지면**(원장님 성함) 안 붙임 | `extractClientName` |

| leaseAmount | 리스금액 | 숫자 + `만원 / 억원 / 억 / 원` | `extractAmount` |

| title | 제목 | 첫 줄 앞 30글자 | `deriveTitle` |

> ⚠️ **되묻기에 대한 답은 분석하지 않고 그대로 저장합니다.** "병원명 알려주세요"에 "한빛의원이요"라고 답하면 값은 `한빛의원이요`가 됩니다.
>
> ⚠️ **수령지는 조용히 채워집니다.** 병원명만 있으면 수령지를 묻지 않고 "병원"으로 넣습니다.

### 선행 업무 예/아니오 판정

`yesNo.ts` `parseYesNo` — 먼저 답변에서 **"기안"이라는 단어를 지운 뒤**, **부정을 먼저** 봅니다.
("기안"의 "안"이 부정어로 오인되던 문제 때문입니다.)

- 부정: 아니 · 아닙 · 아뇨 · 아직 · 미승인 · 미완료 · 대기 · 기다리 · 진행중 · 예정 · 상신 · 결재 전 · 승인 전 · 보류 · 없어 · 못했 · 못받 · 안됐 · 안났 · 안됨 · 안되 · 안했 · 안받 (띄어 쓴 형태 포함) · no → **미완료 → 보류, 안내 문구 발송**
- 긍정: 예 · 네 · 응 · 완료 · 승인 · 했 · 받았 · yes → **완료 → 접수**
- 둘 다 없으면 → "예/아니오로 답해주세요" 다시 질문

> 부정 표현을 추가할 때는 **긍정 답변 안에 들어 있지 않은지** 꼭 확인하세요. 짧을수록 위험합니다
> (예: 예전 규칙의 `"안 "`은 "기안 승인 완료"에 걸려 승인된 요청을 보류시켰습니다).

### 개인정보 표시

`classifier.ts` — 휴대전화번호 또는 주민등록번호 형태가 있으면 요청에 "개인정보 포함" 표시가 붙습니다.

## 5. 무엇을 바꾸려면 어디를 고치나

| 하고 싶은 일 | 고칠 파일 · 위치 |
|---|---|
| 새 표현으로도 분류되게 하기 | `categories.ts` → 해당 소분류 `keywords` 배열에 추가 |
| 두 단어가 **함께** 나올 때만 특정 소분류로 보내기 | `nlp.ts` → `BOOST_RULES`에 규칙 추가 |
| 필수값 항목 추가 · 삭제 · 순서 변경 (되묻는 순서 = 배열 순서) | `categories.ts` → 해당 소분류 `fields` |
| 새로 만든 필드를 문장에서 자동으로 뽑기 | `fieldExtraction.ts` `switch`에 필드 id 추가 + 필요하면 `extract.ts`에 함수 추가 |
| 병원명 뒤 단어가 지점명으로 잘못 붙음 | `extract.ts` → `BRANCH_STOPWORDS`에 그 단어 추가 |
| 품목명 인식 추가 (새 장비 등) | `extract.ts` → `PRODUCT_KEYWORDS` (순서 주의), 모델명은 `PRODUCT_VARIANTS` |
| 캐피탈사 약칭 추가 | `extract.ts` → `KNOWN_CAPITAL_COMPANIES` |
| 선행 업무 추가 (예: 판촉물에도 기안 승인) | `categories.ts` → 해당 소분류에 `prerequisite` |
| 예/아니오 판정 표현 추가 | `yesNo.ts` → `NEGATIVE_PATTERNS` / `POSITIVE_PATTERNS` |
| 데모 판정 조건 | `nlp.ts` → `classifyDemo`와 `classifySubcategory` 첫 두 줄 |
| 2건 분리 연결어 | `nlp.ts` → `MULTI_REQUEST_CONNECTORS` |

### 키워드를 추가할 때 체크리스트

1. **너무 짧은 단어는 피하기** — 2글자 이하는 다른 단어 속에 숨어 있을 확률이 높습니다 ("팁", "sap", "확보").
2. **다른 소분류에 같은(또는 포함 관계인) 키워드가 없는지** 확인하기 — 있으면 동점이 나서 매번 되묻게 됩니다.
3. **표기 변형은 필요한 만큼만** — 키워드 개수가 점수이므로, 한 소분류에만 변형을 잔뜩 넣으면 그쪽으로 쏠립니다.
4. 표현이 새 병원명·품목과 겹친다면 `BRANCH_STOPWORDS` / `PRODUCT_KEYWORDS`도 같이 확인하기.
5. 실제 문장 몇 개로 **바꾸기 전과 후 결과를 비교**하기.

### 아직 남아 있는 것 — 고치려면 분류 결과가 바뀌므로 판단이 필요

| 입력 예 | 현재 결과 | 사람이 기대하는 것 | 원인 (위 문서 해당 절) |
|---|---|---|---|
| 강북의원 수수료 지급 확인 부탁드립니다 | 수수료지급**요청** + 병원명 "강북의원 수수료" | 수수료지급확인 + "강북의원" | `수수료지급`/`수수료 지급`이 공백 제거 후 같은 말이라 2점 (2-②), "수수료"가 제외어에 없음 |
| 성모의원 사업자등록증 첨부합니다 변경 부탁드립니다 | 직접 선택 (동점) | 업체등록/변경 · 매출 | 일정변경의 범용 키워드 `변경부탁`이 1점 → 매출과 동점 |

| 데모 팁 추가 출고 부탁… 알파팁 10개 택배 기안완료 | 데모 · 신규등록 | 출고 · 소모품 (목적: 추가데모팁) | "데모"가 있으면 점수 계산 전에 데모로 확정 (2-①) |
| 예쁨의원 판촉물 리플릿 10부 배너 1개 병원으로 택배 | 품목 = "배너 1개" | "리플릿 10부, 배너 1개" | 품목은 목록 순서상 먼저 있는 **하나만** 뽑음 |

## 7. 개선 제안 (우선순위순)

|---|---|---|---|---|
| 1 | **회귀 테스트 명령** (`npm run check:nlp`) — 실제 문장 + 기대 결과 목록을 파일로 두고 한 번에 전후 비교 | 키워드 하나 고칠 때마다 다른 소분류가 깨졌는지 바로 확인. 이번 검증에 쓴 37건이 그대로 시작점 | 약 1시간 | 없음 |
